# 함께봇 — 사회적기업용 전문가 봇 채팅

운영 기관(지원기관·중간지원조직)이 서버 하나를 띄우면, 여러 사회적기업이 각자 계정으로 로그인해 전문가 봇(Claude)과 사람 전문가를 부를 수 있습니다.

```
            ┌─ 기업 A (계정·채팅방·토큰 지갑) ─┐
 운영 기관 ─┼─ 기업 B                            ├─ 함께봇 서버 ─┬─ Claude API (AI 전문가 봇)
 (관리자)   └─ 기업 C                            ┘               └─ 텔레그램 (그룹 연결 · 사람 전문가)
```

## 할 수 있는 것

**기업(사용자)**
- 아이디·비밀번호로 로그인. 자기 기업의 채팅방·기업 정보·토큰 잔액만 보입니다.
- 채팅방에 AI 전문가 봇 초대 (지금은 마케팅 매니저 봇)
- 채팅방을 텔레그램 그룹(또는 1:1 대화)과 연결해 팀원·외부인과 함께 사용
- 사람 전문가의 프로필·시간당 토큰·상담 가능 여부를 보고 골라서 호출 (검색, 단가순 정렬)
- 호출 → 전문가 텔레그램으로 질문 전달 → 답장이 채팅방에 올라옴
- AI 초안을 사람 전문가에게 검토 요청
- 상담이 끝나면 "상담 시간 × 단가" 계산값을 보고, 원하는 만큼 상담 토큰을 전문가에게 전달

**사람 전문가 (`/expert`)**
- 텔레그램 `/login`으로 받은 1회용 코드로 프로필 페이지에 로그인
- 이름·분야·한 줄 소개·경력과 자격·상담 가능 시간·**시간당 토큰**을 직접 등록 (기업에 보이는 모습을 미리 보며 편집)
- 상담 받기 켜기·끄기, 받은 토큰 잔액과 기록 확인
- 비밀번호 변경

**운영 기관(관리자, `/admin`)**
- 기업 만들기 + 로그인 계정 발급, 계정 추가·비밀번호 재설정·삭제
- 기업별 상담 토큰 충전·차감
- 사람 전문가 등록 (모든 기업이 함께 호출하는 전문가 풀)
- 전문가 받은 토큰 정산 처리
- 전체 거래 기록 (기업별 보기)

## 할 수 없는 것

- **다른 사람이 만든 텔레그램 봇은 부를 수 없습니다.** 텔레그램 봇은 다른 봇의 메시지를 받지 못합니다. BotFather로 직접 만든 봇(토큰 보유)만 연결됩니다.
- 웹앱과 연결되지 않은 텔레그램 대화에서는 봇이 답하지 않고 연결 방법만 안내합니다. 어느 기업의 요청인지 알 수 없기 때문입니다.

## 설치

Node.js 18 이상이 필요합니다. PPT 기능용 패키지 2개(`pptxgenjs`, `jszip`)를 쓰므로 처음 한 번 `npm ci`를 실행하세요.

1. **Claude API 키 발급**: https://console.anthropic.com
2. **텔레그램 봇 만들기**: 텔레그램에서 `@BotFather`에게
   - `/newbot` → 이름 정하기 → 토큰 받기
   - `/setprivacy` → 만든 봇 선택 → `Disable` (그룹의 일반 대화를 웹앱으로 옮겨오려면 필요)
   - 이미 그룹에 넣은 봇이라면, privacy 변경 후 그룹에서 내보냈다가 다시 추가해야 적용됩니다.
3. **설정**: `.env.example`을 `.env`로 복사하고 값을 채웁니다. `ADMIN_PASSWORD`는 필수입니다.
4. **설치·실행**: `npm ci` 후 `node server.js`
   - 기업용: `http://서버주소/`
   - 관리자: `http://서버주소/admin`
   - 전문가용: `http://서버주소/expert`

Docker (이미지 안에서 `npm ci` 실행): `echo {} > data.json && docker build -t hamkkebot . && docker run -p 3000:3000 --env-file .env -v $PWD/data.json:/app/data.json hamkkebot`

텔레그램은 **롱 폴링** 방식이라 웹훅 없이 작동합니다. 인터넷에 공개할 때는 HTTPS(예: Caddy·Nginx 리버스 프록시) 뒤에 두고 `.env`에 `COOKIE_SECURE=1`을 넣으세요.

## 처음 운영하기

1. `/admin`에 관리자 비밀번호로 로그인
2. **기업 만들기**: 기업명, 담당자 이름, 로그인 아이디, 초기 비밀번호 → 기업에 전달
3. 기업 담당자는 로그인 후 **기업 정보**를 채우고, 같은 창의 **비밀번호 변경**에서 비밀번호를 바꿉니다.
4. 필요하면 기업 카드에서 **충전**으로 상담 토큰을 배정합니다.
5. **사람 전문가 등록** → 나온 코드를 전문가에게 전달 → 전문가가 텔레그램에서 봇에게 `/expert 코드` 전송
6. 전문가가 `/login`으로 프로필 페이지에 들어가 **시간당 토큰**을 정하면 기업 목록에 나타납니다. (텔레그램 `/rate 5`로 단가만 바로 정할 수도 있음)

## 텔레그램 그룹 연결

1. 웹앱 채팅방 → **텔레그램** 버튼 → 연결코드 확인
2. 텔레그램 그룹에 내 봇을 추가 (1:1 대화도 가능)
3. 그룹에 `/link 연결코드` 전송
4. 그룹에서 `/mkt 요청내용`, `@봇이름 요청내용`, 또는 봇 메시지에 답장해 봇을 부릅니다.

## 사람 전문가 상담

1. 기업: **전문가 초대** → 사람 전문가 목록에서 단가·프로필 확인 → **호출하기** → 현재 잔액으로 몇 시간 상담할 수 있는지 확인 → 질문 입력
2. 전문가: 텔레그램으로 받은 메시지에 **답장** (진행 중인 상담이 하나면 그냥 보내도 됨)
3. 상담 중에는 채팅방(및 연결된 텔레그램 그룹)의 메시지도 전문가에게 전달됩니다.
4. 종료: 웹앱의 **상담 종료** 또는 전문가의 `/end`
5. 종료되면 채팅방에 **토큰 보내기** 카드가 나타납니다. "상담 90분 × 시간당 6토큰 → 계산 9개"처럼 계산값이 미리 채워져 있고, 기업은 그대로 보내거나 수량을 바꾸거나 "보내지 않기"를 고릅니다. 상담 한 건당 한 번만 처리됩니다.

**잔액이 부족할 때**
- 기업 잔액이 전문가의 **1시간 단가보다 적으면** 바로 연결하지 않습니다. 전문가에게 "잔액 N개, 약 M분 상담분" 경고와 함께 **[수락하고 상담하기] [이번엔 사양]** 버튼을 보냅니다. (버튼 대신 `/accept`, `/decline`도 됩니다)
- 수락하면 그때부터 상담 시간이 계산되고, 사양하면 기업 채팅방에 알립니다. 기업은 기다리는 동안 **요청 취소**를 할 수 있습니다.
- 전문가가 수락하기 전에 보낸 답장은 기업에 전달되지 않습니다.
- 상담 중에 "시간 × 단가"가 기업 잔액에 닿으면(1분마다 확인) 전문가에게 한 번 알리고 **[계속하기] [여기서 마치기]** 중에서 고르게 합니다. 잔액 부족을 알고 수락한 상담에는 이 알림을 다시 보내지 않습니다.
- 계산값이 잔액보다 크면 기업은 잔액만큼만 보낼 수 있고, 토큰 보내기 카드는 남아 있어 충전 후에 보낼 수 있습니다. 같은 상담에 나눠 보내기는 되지 않습니다.

**계산 방식**
- 상담 시간 = 호출한 때부터 상담 종료까지 (분 단위 반올림, 최소 1분)
- 토큰 = 시간당 토큰 × 상담 시간 ÷ 60, 소수점은 올림, 최소 1개
- 단가는 **호출한 순간의 단가로 고정**됩니다. 상담 중에 전문가가 단가를 바꿔도 그 상담에는 적용되지 않습니다.
- 계산값은 안내일 뿐 자동으로 빠져나가지 않습니다. 실제 수량은 기업이 정합니다.
- 상담 시간은 "대화창이 열려 있던 시간"이라 실제 작업 시간과 다를 수 있습니다. 운영 기관에서 기준(예: 답장 기준, 30분 단위)을 정하고 싶다면 `server.js`의 `suggestTokens`를 바꾸세요.

전문가 명령어 (팀방 명령은 위 참고): `/ir` IR 자료 링크 · `/irc 장번호 내용` IR 코멘트 · `/info` 기업 정보 문서 받기 · `/ask 질문` 기업 정보 묻기 · `/accept` `/decline` 잔액 부족 요청 수락·사양 · `/login` 프로필 페이지 코드 · `/rate 숫자` 시간당 토큰 · `/on` `/off` 상담 받기 켜기·끄기 · `/rooms` 진행 중인 상담 · `/end` 상담 종료 · `/balance` 받은 토큰 잔액
기업에는 전문가의 텔레그램 계정이 보이지 않습니다. 여러 기업이 같은 전문가를 동시에 호출해도 답장은 해당 기업에만 전달됩니다.

## 전문가 팀방 (전문가 여럿이 한 텔레그램 그룹에서)

전문가 두 명 이상이 한 기업의 상담을 함께 맡을 때 씁니다. 텔레그램 그룹 하나를 전문가끼리의 "작업실"로 쓰고, 정리된 답만 명령으로 기업 웹앱 방에 보냅니다.

1. 기업이 두 전문가를 각각 **호출** (토큰 계산은 전문가마다 따로)
2. 전문가가 텔레그램 그룹을 만들고 함께봇과 동료 전문가를 초대한 뒤 `/team`
3. `/rooms` → 팀방 전문가들이 맡은 상담 목록 → `/use 1`로 연결
4. 연결되면 기업 방의 새 메시지가 팀방에 보입니다. 팀방 멤버에게는 같은 내용을 1:1로 다시 보내지 않습니다.
5. 팀방의 **일반 대화는 기업에 가지 않습니다.** 기업에 보낼 때만:
   - `/send 내용` (줄여서 `/s 내용`)
   - 동료의 메시지에 **답장**으로 `/s` → 그 메시지 내용을 보냄. 보낸 사람과 쓴 사람이 다르면 "김세무 (이노무 전문가와 함께 정리)"로 표시
6. `/end`는 보낸 사람 본인의 상담만 종료합니다. 팀방 전문가의 상담이 모두 끝나면 연결이 자동으로 풀립니다. 수동 해제는 `/detach`.

**호출되지 않은 전문가의 참여 요청**
7. 팀방의 다른 전문가가 `/join 하고 싶은 말`을 보내면(다른 상담은 `/join 번호 하고 싶은 말`) 기업 채팅방에 **참여 요청 카드**가 뜹니다. 카드에는 이름·분야·시간당 토큰·경력과, 현재 잔액으로 몇 분 상담할 수 있는지가 보입니다.
8. 기업이 **승인**하면 그때부터 그 전문가의 상담 시간이 따로 계산되고, 팀방에 알림이 갑니다. 단가는 **요청할 때 보여 준 단가로 고정**됩니다. 잔액이 1시간 단가보다 적으면 승인할 때 전문가에게도 그 사실을 알립니다.
9. **거절**하면 팀방에 알립니다. 요청 하나당 한 번만 처리되고, 같은 전문가는 기다리는 요청이 있는 동안 다시 요청할 수 없습니다. 상담 받기가 꺼져 있거나 단가를 정하지 않은 전문가는 요청할 수 없습니다.

규칙
- 기업에 보낼 수 있는 사람은 **그 상담에 호출됐거나 참여 승인을 받은 전문가**뿐입니다. 팀방에 있어도 그렇지 않은 전문가는 보낼 수 없습니다(토큰도 받지 않음).
- 팀방이 연결되면 기업 방에 "전문가 팀방이 연결됐어요"라고 알립니다. **연결된 동안 기업 대화는 그 그룹의 모든 사람에게 보이므로**, 팀방에는 함께 상담하는 전문가만 두세요.
- 기업 방과 연결된 그룹(`/link`)은 팀방으로 쓸 수 없고, 팀방은 기업 방에 `/link`할 수 없습니다.
- 한 팀방은 한 번에 상담 하나에만 연결됩니다. 다른 상담으로 바꾸려면 `/use 번호`.

## 기업 정보 문서 (HTML, 버전 관리)

기업마다 "기업 정보 문서"가 하나 있습니다. AI 전문가 봇과 사람 전문가가 그 기업을 이해하는 기준 자료로 쓰입니다.

```
대화 ──함께봇 정리안──┐
전문가 고친 HTML ────┼──▶ 기업이 비교·승인 ──▶ 현재 문서 (v번호) ──▶ AI 봇 문맥 · 전문가 /ask
기업이 웹에서 직접 편집 ─────────────────────▶ (바로 새 버전)     └─ 모든 버전 보관 · 되돌리기
```

**기업 (웹앱 → 왼쪽 "기업 정보 문서")**
- 처음에는 입력한 기업 정보로 v1이 만들어집니다. 모르는 칸은 `[확인 필요]`로 표시됩니다.
- **편집**: 화면에서 바로 고치거나(제목·굵게·목록) "HTML 보기"로 원본을 고칩니다. 저장하면 새 버전이 됩니다.
- **함께봇으로 대화 정리**: 이 기업의 모든 채팅방 최근 대화 80개를 읽고 문서 수정안을 만듭니다. 대화에 없는 사실은 쓰지 않고 `[확인 필요]`로 남기도록 지시합니다. 수정안은 **기업이 승인하기 전까지 반영되지 않습니다.** (AI 키가 없으면 최근 대화 30개를 그대로 붙인 안을 만듭니다)
- **수정안 비교**: 현재본과 수정안을 나란히 보여 주고, 더해진 줄(+)과 빠진 줄(−)을 요약합니다. **승인 / 고쳐서 승인 / 거절(사유)** 중에서 고릅니다.
- **버전 기록**: 모든 버전의 작성자·시각·메모를 보고, 내용을 열어 보고, 내려받고, **이 버전으로 되돌리기**를 할 수 있습니다. 되돌리기는 옛 내용을 새 버전으로 저장하므로 기록이 지워지지 않습니다.
- **HTML 내려받기**: 브라우저에서 바로 열리는 완성된 HTML 파일입니다.
- 편집하는 동안 다른 버전이 승인되면 저장 전에 알려 주고, 확인 후 "그래도 저장"할 수 있습니다.

**전문가 (텔레그램, 상담 중에만)**
- `/info` — 상담 중인 기업의 현재 문서를 HTML 파일로 받습니다. 상담이 여럿이면 `/info 번호` (`/rooms` 순서) 또는 그 기업 메시지에 답장.
- 받은 파일을 고쳐서 **같은 대화에 올리면**(가능하면 받은 파일에 답장으로) 기업에 수정안으로 올라갑니다. 파일 설명(캡션)에 쓴 내용이 메모로 함께 보입니다.
- `/ask 질문` — 함께봇이 기업 정보 문서와 상담방 대화만 근거로 답합니다. 없는 내용은 없다고 답합니다.
- 기업이 승인·거절하면 텔레그램으로 알림이 갑니다.
- 전문가 팀방에서도 `/info`, `/ask`, 파일 올리기를 쓸 수 있습니다(연결된 상담 기준).
- 상담이 끝나면 문서를 받거나 올릴 수 없습니다.

**안전**
- 올라온 HTML, AI가 만든 HTML, 웹에서 저장한 HTML 모두 서버에서 **허용 목록 방식으로 정리**합니다(`doc.js`). 제목·문단·목록·표·굵게·링크 같은 태그만 남기고, 스크립트·스타일·이미지·iframe·이벤트 속성(`onclick` 등)·`javascript:` 링크는 지웁니다. 그래서 색이나 글꼴 같은 꾸밈은 반영되지 않습니다.
- 파일은 1MB, 문서는 300KB까지입니다. 승인본 50개, 거절본 20개까지 보관하고 오래된 것부터 정리합니다(현재본과 기다리는 수정안은 항상 보관).
- 사람 전문가는 상담 중인 기업의 문서만 볼 수 있지만, 한 번 내려받은 파일은 전문가의 텔레그램에 남습니다. 민감한 정보(주민번호, 계좌번호 등)는 문서에 적지 않도록 기업에 안내하세요.

## 일정 봇 (텔레그램 일정방 → 간트차트 일정표)

```
직원들이 텔레그램 일정방에 평소처럼 씀 ──▶ 일정 봇이 추가·연기·취소·완료를 알아듣고 일정표 수정
       ▲                                         │
       └──── "일정표를 고쳤어요 · 링크" ◀────────┼──▶ 기업 웹 채팅방에도 같은 원문·변경 내용·일정표 카드
                                                 └──▶ /g/링크: 간트차트 · 목록 · 상세 계획 · 변경 기록
```

**준비**: 웹앱 채팅방에 **일정 봇** 초대 → 그 방을 직원들이 있는 텔레그램 그룹과 연결(`/link 코드`). 그룹의 privacy mode가 꺼져 있어야 일반 대화를 읽을 수 있습니다(설치 2단계).

**텔레그램 일정방에서**
- 명령 없이 평소처럼 씁니다: "다음 주 화요일부터 3일간 구청 납품 준비, 담당 이수진", "포장 상자 교체 내일 추가", "납품 준비 일주일 연기해요", "포장 교체 취소", "교육 끝났어요".
- 날짜·요일·연기·취소 같은 일정 단어가 들어간 메시지만 AI에 보내고, 일정과 상관없는 말이면 **조용히 넘어갑니다**(회신·토큰 없음). 날짜가 모호하면 되묻습니다.
- 바꾸면 그룹에 "일정표를 고쳤어요 (버전 n) · 바뀐 내용 · **일정표 링크**"를 바로 답합니다. `/sched`로 링크만 받을 수도 있습니다.
- "다음 주 화요일" 같은 말은 서버의 오늘 날짜(한국 시간) 기준으로 계산합니다. 기간은 연기할 때 그대로 유지됩니다.

**기업 웹 채팅방에서**
- 텔레그램 원문과 일정 봇의 변경 내용이 그대로 남고, "일정표 열기" 카드가 붙습니다. 사이드바에 **일정표 (간트차트)** 링크가 생깁니다.
- 기업방에서 일정 봇에게 말해도("포장 상자 교체 취소해 줘") 같은 방식으로 고쳐지고, **텔레그램 일정방에도 같은 내용이 갑니다.**
- **상세 계획**: "구청 납품 준비 상세 계획 작성해 줘" → 목표·날짜별 할 일·준비물·확인할 것을 HTML로 써서 일정표의 그 일정 아래에 넣습니다(모르는 업체명·금액은 `[확인 필요]`).
- **상부 보고 PPT**: "상부 보고용 일정 PPT 만들어 줘" → 현황 숫자·주요 일정 표·변경 사유·위험·다음 단계 장에, **일정 데이터로 직접 그린 간트차트 장**(10개씩)을 넣은 `.pptx`. 텔레그램 일정방에도 파일을 보냅니다.

**일정표 링크 (`/g/…`)**
- 로그인 없이 링크를 아는 사람만 볼 수 있습니다(검색엔진 제외 표시). 간트차트(오늘 선·주말 색·취소는 빗금), 일정 목록, 상세 계획, 변경 기록(누가·텔레그램/기업방·언제)을 보여 줍니다. 스크립트 없는 페이지에 공개 페이지와 같은 보안 헤더가 붙습니다.
- 링크가 새면 `POST /api/sched/token`으로 바꿀 수 있습니다(예전 링크는 바로 404).

**토큰 (관리자 설정)**: 일정 반영 1 · 상세 계획 2 · 보고 PPT 3. 되묻기·링크 안내·일정과 상관없는 메시지는 무료.

## IR 봇 (IR 자료 · 전문가 검토 · VC 찾기)

```
IR 봇 초안 ─▶ 웹 슬라이드(HTML) v1 ─▶ 전문가·기업이 장별 코멘트 ─▶ "코멘트 반영" ─▶ v2 … ─▶ 최종 확정 ─▶ PPTX 내려받기
                     └─ 검토 전문가는 전문가 페이지에서 실시간으로 확인, 새 버전은 텔레그램 알림
```

**IR 자료 만들기·고치기**
- 채팅방에 **IR 봇** 초대 → "IR 자료 초안 만들기". 승인된 기업 정보 문서를 바탕으로 10~14장(표지·한 줄 요약·문제·해결·시장·비즈니스 모델·성과·경쟁 비교·임팩트·팀·재무·투자 유치 계획·마무리)을 만듭니다.
- 슬라이드 종류에 **숫자 카드**와 **표**가 추가됐습니다(성과·경쟁 비교·재무 계획용).
- 매출·시장 규모·투자 금액 같은 숫자는 기업 자료나 코멘트에 있을 때만 쓰고, 없으면 `[확인 필요: 무엇]`으로 남깁니다(웹에서 노란색 표시). 시장 규모를 추정해 채우지 않습니다.
- 이후 요청("재무 계획 장 보강")은 직전 버전을 바탕으로 새 버전을 만듭니다. 최근 30개 버전 보관.

**전문가 참여**
- 기업이 IR 화면 → **검토 전문가**에서 "검토 부탁하기" → 전문가에게 텔레그램 알림과 **바로 열리는 링크**(10분짜리 1회용 로그인 코드 포함)가 갑니다. 지금 상담 중인 전문가도 볼 수 있습니다.
- 전문가는 전문가 페이지(`/expert`)의 **IR 자료 검토**에서 웹 슬라이드를 보고 장별로 코멘트합니다. 텔레그램에서는 알림에 답장으로 `/irc 장번호 내용`.
- 새 버전이 나오면 전문가 페이지가 **새로고침 없이 바로 바뀌고**("v2로 업데이트됐어요"), 텔레그램으로도 알립니다.
- 코멘트가 달리면 기업 채팅방에 알림이 남고, IR 화면의 **코멘트 n개 반영**(또는 채팅으로 "코멘트 반영")을 누르면 IR 봇이 반영합니다. 반영한 코멘트에는 "어떻게 반영했는지" 답글이 붙고, 사실 확인이 필요한 코멘트는 그대로 남습니다. 기업이 "반영 안 함"으로 닫을 수도 있습니다.
- 검토에서 빼면 더는 볼 수 없습니다. 다른 기업은 물론 볼 수 없습니다.

**최종 확정·PPTX**
- **최종 확정**: `[확인 필요]`가 남아 있거나 반영 안 된 코멘트가 있으면 먼저 알려 주고, 그래도 확정할 수 있습니다.
- 확정한 버전만 **PPTX로 내려받기**(`기업명_IR_v2_최종.pptx`). 웹 슬라이드와 같은 배치로 만들어지고 발표자 메모가 들어갑니다. 확정 취소 후 다시 고칠 수 있습니다.

**VC 찾기 (웹 검색)**
- "우리에게 맞는 VC 찾기" → Claude API의 웹 검색 도구(`web_search_20250305`, 최대 6회 검색, 한국 기준)로 투자사를 찾습니다.
- 각 투자사의 출처 URL이 **실제 검색 결과에 있는지 서버가 확인**하고, 확인되지 않는 곳은 뺍니다(뺀 수도 알려 줌). 연락처·투자 조건은 지어내지 않도록 지시합니다.
- 결과는 IR 화면 **VC 후보** 탭에 출처 링크와 함께 최근 5번 검색까지 남습니다. 투자 분야·단계는 바뀌었을 수 있으니 연락 전에 직접 확인하세요.
- 웹 검색은 Anthropic API에서 검색 횟수만큼 별도 요금이 붙습니다.

**토큰 (관리자 설정)**: IR 초안 10 · 수정/코멘트 반영 3 · VC 찾기 5. 코멘트 남기기·검토 전문가 초대·최종 확정·PPTX 내려받기는 무료.

## 마케팅 봇 PPT 만들기 (.pptx)

마케팅 봇에게 "회사 소개 PPT 만들어 줘", "구청 제안용 발표자료"처럼 **PPT·발표자료·슬라이드·프레젠테이션·소개자료**가 들어간 요청을 하면, 글 대신 PowerPoint 파일을 만듭니다.

1. 봇이 승인된 기업 정보 문서를 바탕으로 5~10장 개요를 짜고(기업 분위기에 맞는 색 조합 선택), 서버가 `.pptx`로 만듭니다.
2. 채팅방에 슬라이드 목록, **확인할 것**(문서에 없어 뺀 정보), **PPT 내려받기** 버튼이 나옵니다. 모든 장에 발표자 메모가 들어갑니다.
3. "3번 장을 더 짧게"처럼 말하면 직전 개요를 바탕으로 v2, v3…를 만듭니다(최근 20개 보관).
4. 텔레그램 그룹과 연결된 방이면 `.pptx` 파일을 그룹에도 보냅니다(`/mkt 사업 소개 PPT`).

- 슬라이드 종류: 표지 · 목록+핵심 한마디 · 카드(2~4개) · 단계(3~5개) · 강조 메시지 · 마무리. 번호 원을 공통 장식으로 씁니다.
- 글자 수 상한이 있어 넘치는 글은 잘리고 `…`로 표시됩니다(슬라이드 밖으로 넘치지 않게). 수치·후기·수상·연락처는 지어내지 않도록 지시합니다.
- 글꼴은 맑은 고딕입니다. Mac·Google 슬라이드에서는 비슷한 한글 글꼴로 바뀌어 보일 수 있습니다.
- 파일은 저장하지 않고 개요만 저장해 두었다가, 내려받을 때마다 새로 만듭니다.
- 토큰: 일반 마케팅 요청과 별도 항목 **"마케팅 봇 PPT 만들기" (기본 3토큰)**, 관리자 페이지에서 변경.
- 이 기능 때문에 외부 패키지 2개(`pptxgenjs`, `jszip`)를 씁니다. 처음 설치할 때 `npm install`(또는 `npm ci`)이 필요합니다.

## 홈페이지 봇 (랜딩페이지 제작·게시)

**승인된 기업 정보 문서**를 바탕으로 한 페이지짜리 홈페이지를 만들고, 기업이 확인하면 공개 주소에 게시합니다.

1. 채팅방에 **홈페이지 봇** 초대 → "기업 정보 문서로 랜딩페이지 만들기" (또는 원하는 요청)
2. 봇이 페이지 v1을 만들고, 빠진 정보·확인할 것을 함께 알려 줍니다. 후기·수치·수상·연락처 등 문서에 없는 사실은 넣지 않도록 지시합니다.
3. **미리보기**로 확인 → 고칠 점을 말하면("더 따뜻한 색감으로") 이전 버전을 바탕으로 v2, v3…를 만듭니다. 최근 20개 버전 보관.
4. 주소(`/s/영문주소`)를 정하고 **게시하기** → 로그인 없이 누구나 볼 수 있는 공개 페이지가 됩니다.
5. **등록 확인**: 게시 직후 서버가 공개 주소에 직접 접속해 응답 코드·제목·보안 헤더·스크립트 없음을 확인하고 채팅방에 결과를 남깁니다. 실패하면 실패했다고 알립니다.
6. 다른 버전으로 다시 게시하거나, **게시 중단**할 수 있습니다. 관리자도 기업 카드에서 게시를 중단할 수 있습니다.

`.env`에 `PUBLIC_URL`(예: `https://hamkkebot.example.org`)을 넣으면 안내 메시지에 전체 주소가 나옵니다.

**공개 페이지 안전장치**
- 페이지는 `doc.js`의 `sanitizePage`로 정리됩니다: 스크립트, 이벤트 속성, form·input·button, iframe·svg, 외부 이미지·CSS(`@import`, 외부 `url()`), `javascript:` 링크, `meta http-equiv` 제거. Google Fonts 링크와 `data:` 이미지만 허용.
- 공개·미리보기 응답에는 `Content-Security-Policy: sandbox …; default-src 'none'` 헤더가 붙습니다. 페이지가 별도 출처로 취급되어 함께봇 로그인 쿠키에 접근할 수 없고, 혹시 정리에서 빠진 것이 있어도 스크립트가 실행되지 않습니다.
- 그래서 문의 폼·지도·SNS 위젯처럼 스크립트가 필요한 기능은 넣을 수 없습니다. 문의는 `mailto:`·`tel:` 링크로 합니다.
- 검색엔진(네이버 서치어드바이저, 구글 서치콘솔) 등록과 자체 도메인 연결은 운영 기관이 도메인 소유 확인을 거쳐 따로 해야 합니다.

- 요청 전에 토큰을 먼저 잡아 두고, **답을 받지 못하면 돌려줍니다.** 동시에 여러 요청이 와도 잔액을 넘지 않습니다.
- 잔액이 부족하면 요청하지 않고 채팅방에 알립니다. 텔레그램에서 부른 봇도 그 방의 기업 잔액에서 빠집니다.
- 기업은 봇을 고를 때 요청당 토큰과 잔액을 보고, 봇 답변 옆에 사용한 토큰이 표시됩니다. 관리자 거래 기록에는 "봇 사용 · 봇 이름 · 방"으로 남습니다.
- 새 봇의 기본값은 `bots.js`의 `cost`로 정합니다.
- 전문가의 `/ask`는 지금 토큰을 쓰지 않습니다(운영자 API 비용).

## 기간제 무제한 토큰 (관리자 전용)

관리자 페이지의 기업 카드 → **무제한 토큰 (기간제)** 에서 끝나는 날짜와 "다 쓰면 채울 수량"을 정합니다.

- 기간 동안 잔액이 모자라거나 0이 되면 정한 수량으로 자동으로 다시 채웁니다. 봇 사용, 전문가 호출, 상담 토큰 지급 모두 해당됩니다.
- **기업에는 드러나지 않습니다.** 기업 화면에는 평소처럼 잔액 숫자만 보이고, 무제한 여부·기간·자동 충전 기록은 기업 쪽 응답에 포함되지 않습니다. 잔액 부족 안내, 전문가에게 가는 "잔액 부족" 확인 요청·"잔액 소진" 경고도 생기지 않습니다.
- 관리자에게는 사용 중 표시, 자동 충전 횟수·합계, 거래 기록의 "무제한 자동 충전"이 보입니다. 이 토큰도 전문가 지급에 쓰이면 정산 대상이 되므로 합계를 확인하세요.
- 끝나는 날 자정(한국 시간)에 멈추고 남은 잔액은 그대로 둡니다. "지금 끝내기"로 일찍 끝낼 수 있습니다. 기간은 최대 1년.

## 상담 토큰

```
관리자 ──충전──▶ 기업 지갑 ──상담 종료 후 원하는 만큼──▶ 전문가 잔액 ──정산 처리──▶ (실제 지급은 별도)
```

- 정산 처리는 기록만 남깁니다. 실제 돈 지급(계좌이체 등)은 별도로 하세요.
- 잔액이 남은 기업, 받은 토큰이 남은 전문가는 삭제할 수 없습니다(먼저 차감·정산).

> 주의: 토큰을 돈을 받고 판매하거나 전문가에게 현금으로 바꿔 주는 구조라면, 전자금융거래법상 선불전자지급수단 등 규제 대상인지 법률 검토가 필요할 수 있습니다. 지원기관이 예산으로 배정하는 바우처처럼 운영하는 경우와 요건이 다를 수 있으니 서비스 전에 전문가에게 확인하세요.

## 봇 추가하기

`bots.js`에 객체 하나를 추가하고 서버를 다시 시작하면 웹앱 디렉터리와 텔레그램 명령어(`/id`)에 함께 나타납니다. `soon: true`를 지우면 '준비 중' 봇이 활성화됩니다.

```js
{
  id: 'fund',                 // 영문 소문자 — 텔레그램 명령어 /fund
  name: '지원사업 코치 봇', short: '지', color: '#2a9d8f',
  tag: '공모·지원사업', desc: '지원사업 공고와 사업계획서 초안을 돕습니다.',
  hello: '안녕하세요, 지원사업 코치입니다.',
  quick: ['사업계획서 목차 초안'],
  role: `당신은 사회적기업 지원사업 전문 코치입니다. ...`
}
```

## 봇 마켓 (기업이 직접 만든 봇)

1. **만들기**: 웹앱 「전문가 초대 → + 봇 만들기·올리기」에서 *Claude 안내문*을 복사해, 원하는 봇 설명을 덧붙여 Claude에게 보냅니다. Claude가 봇 정의(`<script id="hamkkebot-bot">` JSON)를 담은 아티팩트를 만듭니다.
2. **올리기**: 아티팩트를 공개 공유한 링크를 넣고 「링크 읽기」, 링크가 안 읽히면 정의 JSON을 붙여넣습니다. 미리보기를 확인한 뒤 기업방에 승인을 요청합니다.
3. **기업방 승인**: 채팅에 승인 카드가 뜨고, 승인하면 우리 기업 봇 목록에 올라갑니다. 업데이트도 같은 방법으로 올리고 승인받으면 버전이 올라갑니다.
4. **종류**: `chat`(글 답변, PPT 옵션), `site`(홈페이지), `ir`(IR 자료), `sched`(일정). 기존 봇 기능을 그대로 쓰고, 역할 지시문이 그 위에 더해집니다.
5. **다른 기업에 공개**: 만든 기업이 가격(요청당 추가 토큰 그리고/또는 N일 이용권 가격)을 정하고 공개를 요청하면, 운영 기관 관리자가 「봇 마켓 심사」에서 승인·거절합니다. 공개 중인 봇을 업데이트하면 다시 심사를 받습니다.
6. **토큰 나눔**: 다른 기업이 쓰면 기본 봇 비용은 운영 기관에, 요청당 몫은 만든 기업 지갑으로 갑니다. 이용권 기간에는 요청당 몫이 없습니다. AI 실패 시 이용 기업에 모두 돌려주고 만든 기업 몫도 생기지 않습니다. 거래 기록에 보냄·받음이 남습니다.
7. **보안**: 링크 읽기는 http/https 공개 주소만, 내부망·메타데이터 주소와 그쪽으로 가는 리다이렉트를 막고, 300KB·8초로 제한합니다.

## 시험 (`npm test`)

`tests/`의 시험은 가짜 텔레그램·Claude 응답으로 서버 흐름을 확인합니다. 실제 API를 호출하지 않고, 임시 파일에 데이터를 써서 `data.json`을 건드리지 않습니다.

- `multitenant` — 기업 간 데이터 분리, 로그인·비밀번호, 토큰 충전·지급·정산, 텔레그램 그룹 연결
- `expert-rate` — 전문가 프로필·단가, 상담 시간 × 단가 계산, 단가 고정
- `low-balance` — 잔액 부족 시 전문가 수락·사양·취소, 잔액 소진 경고
- `team-room` — 전문가 팀방 `/use` `/send` `/end`, 자동 연결 해제
- `join` — 호출되지 않은 전문가의 `/join` 요청, 기업 승인·거절, 단가 고정
- `sched` — 텔레그램 일정방 자동 반영(추가·연기·취소)·관련 없는 말 무시·되묻기·링크 회신·기업방 동기화·일정표 페이지·상세 계획(스크립트 제거)·보고 PPT 간트 장·링크 바꾸기
- `ir` — IR 초안·장별 코멘트(웹·텔레그램 `/irc`)·검토 전문가 권한(초대·상담 중·빼기)·코멘트 반영과 답글·없는 코멘트 무시·확정 경고·최종 PPTX·VC 웹검색(일시정지 이어받기, 출처 미확인 제외)
- `unlimited` — 기간제 무제한: 날짜·수량 검사, 모자라면/다 쓰면 다시 채움, 기업 응답에 흔적 없음, 전문가 호출·지급·잔액 소진 경고 생략, 끝내기·만료 후 정상 동작
- `ppt` — PPT 요청 판별·별도 토큰, .pptx 내용(장 수·발표자 메모·글자 수 자르기·빈 폴더 없음), 수정 버전, 실패 시 환불, 다른 기업 차단, 텔레그램 그룹으로 파일 전송
- `site` — 페이지 정리기 공격 사례, 봇 토큰 차감·부족 차단·실패 시 환불·사용량 설정, 홈페이지 봇 생성·수정, 미리보기 권한, 게시·주소 규칙·중복, 등록 확인, 공개 주소 보안 헤더, 게시 중단
- `mkt-doc` — 마케팅 봇이 승인된 문서만 문맥으로 쓰는지 (저장 → 전문가 수정안 대기 → 승인 → 되돌리기). `VERBOSE=1 node tests/mkt-doc.test.js`로 봇이 받은 기업 정보를 직접 볼 수 있음
- `doc` — HTML 정리기 공격 사례, 문서 저장·충돌·되돌리기·다운로드, 함께봇 정리안, 전문가 `/info`·`/ask`·파일 올리기, 승인·거절, 상담 종료 후 차단
- `migration` — 이전 버전 데이터 옮기기, 실시간 알림 분리

## 보안

- 비밀번호는 scrypt로 해시해 저장합니다. 로그인은 HttpOnly 쿠키 세션(14일)입니다.
- 로그인 실패가 IP당 10분에 10번을 넘으면 잠시 막습니다.
- 비밀번호를 바꾸거나 관리자가 재설정하면 그 계정의 다른 로그인은 끊깁니다.
- 모든 채팅방·결제 요청은 서버에서 "로그인한 기업의 것인지" 확인합니다. 다른 기업의 방은 없는 것으로 처리됩니다.
- `data.json`에 모든 데이터가 들어 있습니다. 정기적으로 백업하고 외부에 노출되지 않게 하세요.

## 이전 버전에서 올라오는 경우

기존 `data.json`이 있으면 첫 실행 때 그 데이터(채팅방·기업 정보·토큰 잔액·거래 기록)를 기업 하나로 옮깁니다. 그 기업에는 계정이 없으므로, 관리자 페이지에서 그 기업 카드의 **계정 추가**로 로그인 계정을 만들어 주세요. `APP_PASSWORD`는 더 이상 쓰지 않습니다.

## 현재 한계 (시제품)

- 데이터는 `data.json` 파일 하나에 저장됩니다. 기업이 수십 곳을 넘거나 동시 사용자가 많아지면 데이터베이스(PostgreSQL 등)로 옮기는 것이 좋습니다.
- 방마다 최근 500개 메시지만 보관합니다.
- 관리자는 비밀번호 하나로 들어가며, 관리자 여러 명 구분이나 작업자별 기록은 없습니다.
- 기업 담당자가 비밀번호를 잊으면 관리자가 재설정해야 합니다(이메일 찾기 없음).
- 예약·대기열 기능은 없습니다. 상담 가능 시간은 전문가가 적은 안내 문구일 뿐 시스템이 막지는 않습니다.
- 전문가 단가 상한은 1,000토큰이며 운영 기관이 승인하는 단계는 없습니다.
- 봇 답변은 초안입니다. 수치·인증·성과는 직접 확인 후 사용하세요. API 사용료(Claude)는 서버 운영자에게 청구됩니다.
